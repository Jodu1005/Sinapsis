SINAPSIS / PROJECT ARCHITECTURE

Sinapsis 完整项目架构

Sinapsis 是一个运行在开发者本机的 Agent 控制室。它把全局 Agent、频道、工作空间与 Git worktree 组合起来，让人能创建任务、观察 Runtime 输出、干预执行并进行人工验收。

单进程本地服务React + ExpressSQLite 为事实来源更新时间：2026-08-05

系统总览

浏览器通过 Vite 代理访问本地 API 和 SSE；服务只监听 127.0.0.1。

→
PortsRepository、Runtime、Git、worktree、事件、时钟
→
AdaptersSQLite、SSE、Git CLI、OpenCode、Pi、Claude Code

本地优先

用户数据保存在 ~/.sinapsis：SQLite、工件、会话文件和 worktree 都不依赖云端服务。

人保持控制权

Agent 产出进入 in_review 后，只有人能做 accept 或 return。产品不自动 merge 或 push。

可替换 Runtime

Runtime 通过统一端口接入；每个 Agent 配置命令、参数、模型和环境变量。

核心领域模型

领域主要实体核心关系负责的规则
WorkspaceWorkspace、Repository、ChannelWorkspace 拥有多个 Repository；Channel 可绑定多个 Workspace。仓库必须是有效 Git 仓库；频道绑定受上限和未完成任务约束。
AgentAgent、Runtime ProfileAgent 是全局实体，通过 membership 加入普通 Channel。mention 唯一、能力标签匹配、idle/busy/offline 状态。
TaskTask、Lease、Session、Artifact、ReviewTask 属于 Channel 和 Repository；一个 Lease 指派给一个 Agent。严格状态转移、FIFO 认领、人工输入、评审与重试。
ExecutionTaskExecution一次 Runtime 执行绑定一个 Task、Agent 和可选 worktree。同一 Task 或 worktree 不能同时有两个 active execution；重启后 active execution 被隔离。
ConversationTurn、Participant、Invocation、Handoff人类消息触发 Turn；多个 Agent invocation 按队列与轮次运行。提及路由、参与选择、去重、handoff、取消和恢复认领。
MemoryDreamRun、Candidate、Memory、ThreadSummaryDream 从频道增量消息中提取候选记忆；人审核后形成记忆。候选溯源、频道边界、重复内容、归档和重启恢复。

关键运行流程

任务创建、认领与执行

创建 TaskAPI 校验频道、workspace、repository 和 Agent 约束
→
Scheduler为 idle Agent 以 FIFO 认领，并创建 lease
→
Execution Reservation持久化 starting record，阻止同一任务重复启动
→
Git Worktree创建任务分支与隔离目录
→
Runtime记录 session 后激活 execution，流式保存工件

Runtime 成功且分支有提交时，任务进入 in_review。失败、取消、超时会结束 execution、释放 lease 和 Agent；人工验收不会自动合并代码。

服务重启保护

服务启动迁移 SQLite，并恢复频道会话与 Dream
→
扫描 active execution查找 starting / running 的持久化记录
→
标记 orphaned记录 service_restarted，不自动复用 worktree
→
needs_human释放 lease，等待人确认旧进程和工作目录状态
安全策略 重启后宁可停在人工处理，也不自动重跑可能仍被旧 Runtime 写入的 worktree。这个策略优先保护代码和 Git 历史。

频道消息与协作会话

Human Message持久化消息与 thread 归属
→
Mention Router识别 @Agent，校验频道成员
→
Turn Coordinator建立 Turn，选择参与者和 invocation
→
Conversation Session按 Agent 队列调用 Runtime
→
Public Reply写回消息、handoff 与 turn 状态

持久化、事务与事件

SQLite 是事实来源

Repository 的写操作使用 BEGIN IMMEDIATE。领域事件通过 afterCommit 在提交后发布，因此浏览器不会看到已回滚的数据变化。

数据表分组

workspaces / repositories / channels / agents；tasks / task_leases / task_sessions / task_executions / artifacts；messages / conversation_*；dream_runs / memory_* / thread_summaries。

事件链生产方消费方用途
task.*、agent.*、message.*SQLite Unit of Work、Task coordinatorSSE Publisher、React刷新可见任务、消息和状态。
conversation.*ChannelTurnCoordinatorSSE Publisher、React展示参与者、调用、handoff 和运行活动。
dream.*、memory.*DreamRunService、MemoryReviewServiceSSE Publisher、React同步候选记忆和审核结果。

前端架构

状态入口

WorkspaceShell 获取 bootstrap、保存频道选择、加载任务和 turn 详情，并向子组件传递动作。ApiClient 处理请求与 human capability header。

实时更新

useWorkspaceEvents 使用 EventSource 监听领域事件。当前实现以全量 bootstrap 刷新为主，Runtime 高频事件做 200ms 合并。

主要 UI 模块包括频道时间线、任务列表与详情、Agent 配置、频道成员与 workspace binding、会话 Turn 详情、Dream Center 和 Memory Candidate 评审。前端的 workspace-view.ts 是浏览器专用的安全 DTO，Runtime 环境变量只暴露变量名。

启动、配置与验证

进程生命周期

main.ts 建立 app，恢复 orphaned Agent、Dream 和记忆、对话 invocation 与 task execution；随后启动 task scheduler、lease reaper 和可选 Dream scheduler。关闭时依次停止循环、Runtime、SSE、HTTP 和 SQLite。

环境配置

SINAPSIS_DATA_DIR 指定数据目录；SINAPSIS_PORT 指定本地端口；Dream 的 runtime、时间、时区、并发与超时由对应的 SINAPSIS_DREAM_* 配置控制。

当前架构边界

已经完成 Runtime 执行的持久化所有权、启动时隔离、worktree 并发保护、Runtime 公共契约迁移到 ports、任务执行器和消息服务的最小依赖接口。
后续演进方向 会话协调器仍然较大；API bootstrap 仍是一个较粗的读模型；SQLite Repository 还需要按 Task、Conversation、Memory 和 Channel 拆分为多个 store。它们适合后续独立迭代，不影响本轮执行安全保护。
本文档描述当前项目结构，而不是产品宣传页。重构路线请参阅 architecture-refactoring.html。
