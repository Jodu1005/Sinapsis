# Summit 频道上下文清空设计

## 目标

将当前的圆桌会议频道命名为 `summit`，并把它作为唯一允许清空上下文的特殊频道。清空操作为逻辑清空：新的对话和任务不再看见旧上下文，但不删除任务生成的 Git worktree、证据文件或产物。

## 频道配置

新增共享频道策略配置，集中定义：

- 特殊频道的规范名称为 `summit`。
- `summit` 具备 `resetContext` 能力。
- 所有其他频道均不具备该能力。

前端用该配置决定是否显示操作；服务端用同一配置校验请求，不能只依赖界面隐藏按钮。

## 数据模型

为 `channels` 增加可空的 `context_reset_at` 时间戳，并映射到频道视图。

该时间戳是上下文代际边界：频道中的消息和任务仅在其创建时间晚于该时间戳时，才属于当前上下文。旧记录继续保留在数据库中，供证据保留、调试和文件回收使用，但不出现在频道时间线、任务列表或 Agent 提示词中。

## 清空流程

仅 `summit` 可调用 `POST /api/channels/:channelId/context-reset`：

1. 校验频道存在、未归档且具有 `resetContext` 能力。
2. 停止该频道正在进行的普通对话 Runtime。
3. 取消该频道尚未结束的任务，释放租约和 Agent 空闲状态，并停止对应 Runtime 会话。
4. 在单个事务中写入新的 `context_reset_at`。
5. 通过现有 SSE 事件使客户端刷新。

清空不删除 Git 分支、worktree、运行证据、产物文件或旧的数据库记录。

## 界面

频道右侧“频道操作”区仅在当前频道是 `summit` 时显示“清空上下文”危险操作。执行前显示明确确认对话框，说明会终止进行中的任务并隐藏当前频道的消息、Thread 和任务历史，但会保留本机文件。

普通频道不显示该按钮，即使构造请求也会被服务端拒绝。

## 验证

- 配置测试：仅 `summit` 获得能力。
- 服务测试：普通频道请求被拒绝；`summit` 会取消活动任务、停止对话，并更新边界时间。
- 数据测试：边界之前的消息和任务不出现在 Bootstrap 快照；证据和 worktree 路径保持不变。
- 界面测试：仅 `summit` 显示按钮；确认后刷新为空状态；普通频道没有该操作。
