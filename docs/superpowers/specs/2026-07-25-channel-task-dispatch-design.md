# 频道创建与聊天任务派发设计

## 目标

让工作空间中的频道可由用户自行创建，并让用户可在当前频道的聊天框中直接派发可执行任务。普通聊天不得被误创建为任务。

## 范围

- 在当前工作空间的侧栏“频道”标题旁提供新增频道入口。
- 新频道仅需要名称，创建成功后自动切换至该频道。
- 聊天框支持显式命令：`/task <任务描述>`。
- `/task` 创建的任务归属当前频道，并进入现有任务队列。
- `/task` 中的首个 `@Agent身份` 作为定向执行人；没有匹配提及时保持非定向，交由空闲兼容 Agent 按队列领取。
- 普通消息继续走既有频道消息流程，不创建任务。

## 交互

### 新增频道

1. 用户在侧栏“频道”旁点击加号。
2. 弹窗输入频道名称并提交。
3. 客户端调用现有的仓库级创建频道接口，成功后刷新工作空间快照并切换到新频道。
4. 名称为空、重复或服务端失败时，在弹窗内显示错误，既不切换频道也不丢失输入。

当前工作空间可能包含多个内部仓库；频道仍由后端挂在仓库上。本版本把新频道创建到当前工作空间的首个工作目录，和“新建任务”采用相同的默认归属规则。界面不暴露仓库层级。

### 聊天框任务命令

1. 用户输入以 `/task` 开头、后跟非空描述的消息并发送。
2. 客户端解析可选的首个 `@身份`，移除该提及后，以其余文本作为任务标题和描述。
3. 客户端以当前频道、当前工作目录调用任务创建接口；若身份不匹配，显示错误且不创建任务。
4. 成功后刷新快照，任务出现在左侧任务列表和右侧频道任务中。既有调度器负责后续领取与 Agent 频道回复。
5. 输入为 `/task` 或 `/task @身份` 时，不发送普通消息，聊天框显示“请补充任务内容”。

为了避免意图猜测，普通文本和仅含 `@身份` 的文本始终作为普通频道消息发送。

## 实现边界

- 复用 `WorkspaceService.createChannel` 与 `TaskService.createTask`，不增加新的后端持久化模型。
- API 客户端增加创建频道调用。
- 将命令解析封装为独立、可单测的前端函数；界面只根据解析结果选择“发消息”或“创建任务”。
- 新增频道弹窗沿用现有工作空间创建弹窗的可访问性与错误展示模式。

## 验证

- 单元测试覆盖命令解析：普通消息、无描述、非定向任务、定向任务、未知 Agent。
- 组件测试覆盖侧栏频道创建入口、创建后选择频道，以及聊天框任务派发调用。
- 全量测试、生产构建和浏览器验收：新频道可见并自动选中；`/task` 创建任务而不产生重复普通消息。
