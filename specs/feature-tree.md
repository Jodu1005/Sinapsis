# 功能树：Agent 控制室

状态：草案  
对应设计：[受 Raft 启发的 Agent 控制室](../docs/raft-control-room-design.md)

## 使用规则

- 这是实现范围的唯一功能索引，不是待办事项列表。
- 每个功能必须有阶段、父节点和可观察的完成条件。
- 原型 1 之外的节点不能为赶进度提前实现。
- 状态词与设计文档一致：待开始、已领取、执行中、等待输入、审查中、已接受、已驳回、已失败。

## 原型 1 的交付切片

原型 1 只包含以下闭环，顺序不可颠倒：

1. F0.1、F0.2、F0.3、F1.1、F1.2、F1.3：用户能选仓库，确认其 Git 状态，配置并验证一条命令。
2. F2.1、F2.2、F2.3、F2.4、F2.5、F3.1、F3.2、F3.3、F3.4：用户能在一个隔离工作区里启动、观察和停止一次任务，并能追踪任务状态与分支。
3. F4.1、F4.2、F4.3、F4.4、F4.5、F4.6：用户能审查一次结果、查看测试输出并留下决定。
4. F5.1、F5.2、F5.3：上述能力在三个界面中形成可演示流程。

以下节点即使实现简单，也不进入原型 1：F1.4、F3.5、全部 F6、全部 F7。它们应先在原型 1 闭环稳定后再重新排期。

## 原型 1 的验收映射

| 用户结果 | 所需节点 | 验收证据 |
| --- | --- | --- |
| 在 2 分钟内连接仓库并配置 Agent | F0.1、F0.2、F0.3、F1.1、F1.2、F1.3 | 新项目、Git 基础状态与已验证命令被保存 |
| 启动隔离任务并看到过程 | F2.1、F2.2、F2.3、F2.4、F2.5、F3.1、F3.2、F3.3 | worktree 路径、任务状态、分支关系、实时输出、会话状态 |

| 审查实际改动 | F4.1、F4.2、F4.3、F4.4、F5.3 | 文件列表、diff、退出码、测试输出 |
| 作出并保留决定 | F4.5、F4.6 | 任务状态和决定记录 |

## 不变量

- 一个任务在任一时刻只能有一个负责人。
- 一个会话只属于一个任务和一个 Agent 席位。
- 任务状态与会话状态必须分开保存。
- 未经人工接受，Agent 改动不能被标记为已完成或自动合并。
- 无法建立 worktree 时，不能静默在主工作目录执行。
- 任何状态变化必须有可追溯事件或人工决定记录。
